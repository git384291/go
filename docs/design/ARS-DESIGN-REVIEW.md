# ARS 설계 검토 (검토 전용 — 구현·연결·비용 없음)

- 근거: PM 7011892065 지시문의 ARS 조건. **공개 자료를 새로 조사해 확인한 사실은 아직 없다.** 아래는 설계 시 충족해야 할 조건과 확인 상태이며, 법령·업체 약관 해석은 확인 전까지 **미확인**으로 둔다.
- 범위 밖(이 문서가 승인하지 않는 것): 실제 ARS 개설·번호 발급·통화·녹취, 업체 가입·결제, 채널 개설, 네이버·카카오톡 연결, 실고객 연결, 공개 배포, 비용 발생, "암호화되어 안전합니다" 같은 보증 문구.
- 이 저장소의 화면·서버에는 ARS 코드가 없고 이 문서로 만들지 않는다.

## 조건별 설계 검토

| 조건 | 설계 원칙 | 확인 상태 |
|---|---|---|
| 직접 입력 주체 | 고객이 키패드로 넣는 정보(연락처·설치 희망 등)는 **검증된 총판 또는 ARS 제공자**가 직접 받는 경로에서만 입력한다. FIDEON 화면·서버·Claude는 그 입력값을 받지 않는다. | 총판·제공자의 실제 접수 방식 **미확인** |
| 수신 주체 | 통화를 받는 쪽(총판 상담원·제공자·FIDEON)을 통화 시작 안내에서 말하고, 사람이 받는지 자동 응답인지 구분해 알린다. 수신 주체가 확인되지 않으면 연결하지 않는다. | **미확인** |
| 동의 | 입력·녹취 전에 목적, 받는 항목, 처리하는 곳, 보관 기간을 안내하고 고객이 동의 의사를 밝힌 뒤에만 진행한다. 동의하지 않아도 쓸 수 있는 다른 방법(예: 화면 비교만)을 둔다. | 필요한 동의 형식·문구는 법령·총판 약관 **미확인** |
| 녹취·키패드 입력 저장/삭제 | 녹취와 키패드 입력은 저장 여부, 저장 위치, 보관 기간, 삭제 방법·시점을 정하고 안내한다. 정해지지 않은 항목이 있으면 저장하지 않는다. 주민등록번호·신분증·계좌 정보는 입력받지 않는다. | 저장 위치·기간 **미정** |
| 접근 권한 | 녹취·입력값을 볼 수 있는 사람과 권한 범위를 최소로 정하고 열람 기록을 남긴다. FIDEON 관리자 화면에서는 마스킹된 값만 본다. | 권한 구조 **미정** |
| 인계 결과 확인 | 담당자 수신은 **업체가 주는 확인 신호**가 있을 때만 '확인'으로 표시한다. 신호가 없거나 늦거나 다른 통화의 신호이면 '전달 결과 불명'으로 두고 "접수됨"을 말하지 않는다(PR 7010893389 네 상태와 같은 원칙). 담당자 수신과 총판 접수는 별개다. | 업체의 수신 확인 신호 존재 여부 **미확인** |

## 통화 안내에 쓰지 않는 말
- "암호화되어 안전합니다" 등 근거 없는 보안 보증, 접수·가입·개통 완료 표시, 금액·일정 확정, 사람 상담원으로 오인될 표현.
- ARS가 AI인지 녹음된 안내인지 숨기는 표현. AI 응답을 쓴다면 그렇다고 알린다.

## 열린 질문(결정 전에 확인할 것)
1. 총판 또는 제공자가 전화로 받는 접수 항목과 처리 주체는 누구인가?
2. 녹취·키패드 입력을 어디에 얼마나 보관하고 어떻게 삭제하는가?
3. 인계 성공을 알려 주는 신호가 업체 공식 문서에 있는가?
4. 이 모든 것이 확정되기 전까지 전화는 모의 버튼(현재 시안)만 둔다.
