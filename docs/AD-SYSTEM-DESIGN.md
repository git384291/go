# 전국 광고 시스템 설계안 (PM 11/22, 기준 SHA 5c79a8e) — 설계만, 코드·실계정·집행 없음

목표: 전국 24시간 AI 상담 연결 + 유효 접수 확대. 하루 30건은 목표 지표일 뿐 광고 예산의 근거가 아니며, 광고비는 설치당 마진에서 역산한다(§7). 최적화 기준은 클릭이 아니라 **유효 접수 → 설치 완료 → 최종 순마진**.
범위: 사업자등록 전 판매 가능 상품인 **인터넷+TV 결합(`internet_tv`, DB 상태 active)만** 광고 대상. 나머지(`internet_phone`·`internet_only`·`cctv_security`·`mobile`·`other`)는 reserved → 광고·키워드·소재 금지.
표기: **[확인]** 공식 문서로 확인 · **[미확인]** 공식 확인 전(계정 개설·심사 시 확인 필요) · **[가정]** 시뮬레이션용 임시값.

## 5. P1 위험: Google 일예산 2배 지출

- **사실 [확인]**: Google은 트래픽 변동 대응으로 특정일 평균 일예산의 **최대 2배**까지 지출할 수 있고, 월 청구는 평균 일예산의 **30.4배**를 넘지 않는다.
- **현재 코드의 빈틈**: `adRun.ts`는 매체 일예산 ≤ 승인액(`amountKrw`, 최대 `AD_DAILY_CAP_KRW` 10,000원)이면 안전으로 본다. 그러나 일예산을 승인액과 같게 두면 **하루 최대 2 × 승인액(20,000원)** 이 나갈 수 있다 → 승인 한도 초과 가능. `ad_performance.over_ledger`·`judgeSpend`는 **사후 보고값**으로만 잡으므로(매체 보고 지연) 당일 초과를 막지 못한다. 첫 3일 총 한도(30,000원)도 하루 20,000원 지출 시 이틀째 초과 가능.
- **운영 차단 기준(설계)**:
  1. 매체 일예산 = ⌊승인 일 한도 ÷ 2⌋ (최악의 날도 승인 한도 이내). 대가: 평균 노출 감소.
  2. 기간 총 한도는 매체에도 설정 가능한 경우(캠페인 총예산 등) 동일 값으로 [미확인: Search 캠페인 지원 여부].
  3. 당일 누적 지출이 승인 일 한도의 80%면 경고, 100%면 즉시 일시중지 요청(`searchAdStop`), 지출 미상·보고 지연 2시간 초과면 중지(fail-closed).
  4. 실제 청구(billed)와 노출 비용(served) 차이는 대시보드에 따로 표시.
- **P1 안전장치 반영(PM 11/22 2차 지시, 실계정·실지출 없음)**: ① 매체 일예산 = 승인액 ÷ 2(`platformDailyBudgetFor`, 어댑터도 2배 초과 설정은 전송 전 거부) ② DB 지출 판정 계정 합산(0020: 모든 캠페인 당일 1만·누적 3만, 다른 캠페인 launch가 열려 있으면 차단) ③ 보고 지연은 0원이 아니라 UNKNOWN(기록 안 함, 계정 판정 STOP_REQUIRED) ④ 중지 실패 경고가 하나라도 열리면 계정 전체 지출 차단(fail-closed) ⑤ 집행 전 계정의 ENABLED 캠페인(외부 생성 포함) 조회 — 1개 이상이거나 조회 실패면 차단. 재현 시험 OS1~OS5는 같은 시나리오로 유지하고 기대값을 수정 후 동작으로 바꿨다.
- **P0 2건 반영(PM 11/22 3차, 0021)**: ① 집행 기간을 DB가 정한다 — 종료일 = min(오늘+2, 승인 만료 시각이 속한 날짜−1, KST). 종료일 다음 날 0시 ≤ 승인 만료이므로 72시간 승인이 4개 날짜에 걸쳐도 집행은 최대 3개 날짜. 날짜별 최대 청구 가능액(승인액 = 매체 일예산 승인액÷2 × 2배)을 `core.ad_exposure`에 기록하고 계정 날짜별 1만·누적 3만을 그 최대값으로 판정(넘길 가능성이 있으면 차단). ② 매체 종료일 `end_date_time = 종료일 23:59:59`(v23+ 필드, 고객 계정 시간대, 검색 캠페인은 일 단위)를 설정하고 종료일·계정 시간대(Asia/Seoul)를 read-back해 다르거나 미확인이면 즉시 중지·집행 금지. ③ 정기 감시(`/api/internal/ad-monitor`, 전용 DB 역할 `app_ad_monitor`): 종료일 경과·승인 만료·날짜별 초과·계정 3만 도달 시 중지, 보고 지연·조회 실패·불명 launch는 기록 ok=false → 새 집행 `MONITOR_NOT_OK`, 2시간 안에 기록 없으면 `MONITOR_STALE`, 중지 실패는 경고(계정 전체 `STOP_PENDING`).
- 남은 항목: 스케줄러 등록(배포 승인 사항), 실제 계정 read-back·end_date_time 동작 확인, billed/served 분리 표시. 네이버·카카오 일예산 초과 규칙은 같은 방식으로 확인 후 반영.

## 6. 가격·사은품·표현 규칙 (PM 11/22 정정 반영)

- **브랜드**: 고객 화면·광고 모두 **FIDEON(피데온)** 하나로 통일. 다른 상호·통신사 직영·"공식" 오인 표기 금지.
- **가격·사은품은 승인·게시된 최신 총판 정책 값을 그대로** 쓴다. 출처는 `core.policy_versions`(승인 `approved` 상태 + 게시 스위치 `policy_publish` 켜짐, `api.policy_published()`)뿐이다. 이미 상담(`publishedPolicies.ts`, quote 경로)이 쓰는 같은 출처를 광고도 읽는다 → 광고·상담 값이 어긋날 수 없다.
- **AI는 가격·할인·사은품 금액을 만들거나 바꾸지 않는다.** 소재 문안은 정책 값을 '자리표시자'로만 참조하고 서버가 게시된 값으로 채운다(AI 출력에 금액 숫자가 있으면 BLOCK).
- **정책이 바뀌면** 승인·게시된 최신 버전만 반영한다. 대체된(superseded)·만료(`valid_until`)·초안 값은 광고·상담에서 즉시 제외. 소재의 정책 참조는 버전 번호를 기록해, 최신이 아니면 게시 BLOCK·자동 중지 후보로 표시.
- **대표 검토의 의미**: 소재 검토는 디자인·문구·표현 검수이다. 이미 승인된 정책 가격·사은품을 소재마다 새로 결정하는 절차가 아니다(승인 화면에는 "정책 vX 값 그대로" 표시만).
- **별도 계산 항목**: 휴대폰 결합할인·위약금 지원처럼 고객별 조건이 필요한 값은 광고에 금액으로 넣지 않고, 실제 조건 확인 뒤 상담에서 별도 처리한다(광고 문구는 "상담 시 확인" 수준).
- 표현 차단 패턴(초안): 정책에 없는 금액·할인율, 정책 값과 다른 사은품, 최저·최대·최고·1위·100%·무조건·공짜, 통신사 직영·본사 오인, 당일 설치 보장, 통신사 로고·상표(총판 허용 범위 확인 전). 소재 생성 결과·수동 소재·랜딩 문구 모두 같은 필터 → 위반 시 집행 BLOCK(`CAMPAIGN_BLOCKERS` 확장).
- 저장소 점검: 승인 정책 **데이터**는 저장소에 없다(정책은 운영에서 입력·승인, 게시 스위치 기본 꺼짐). 실제 값이 입력·게시되기 전에는 광고 소재의 금액 칸은 비어 있어 금액 표기가 나가지 않는다.
- 결합상품 경품 법정 상한은 과거 방통위 고시 기준이 있었다(2019 기사). 2026 현재 유효 여부·소관은 미확인 — 총판 정책 값이 이 범위 안인지 확인은 총판 책임 사항으로 두고, 우리는 승인 값을 변조하지 않는 것까지를 보장한다.

## 7. 수익성 역산 시뮬레이터 설계 (PM 11/22 2차 정정 — 기준 SHA fc3b1fb)

**이전 판의 가정값(위약금 지원 8,000원·환수율 10%·세금 예비 9,000원·운영비 5,000원), 사전 순마진 59,000원, 손익분기 CPC 944원/472원, 시나리오 A~E 표는 모두 운영 기준에서 제거한다.** 근거 없는 임의값이었다. 확인되지 않은 항목은 아래처럼 **미확정**으로 둔다.

### 7.1 원칙
- 운영 판단에는 **확인된 값만** 쓴다. 미확정 항목이 하나라도 있으면 순마진·손익분기·허용 광고비를 **계산하지 않고 '미확정'으로 표시**한다.
- 설치 1건당 90,000원은 대표가 말한 **계획 마진(사은품 제외 후)**일 뿐 **확정 평균이 아니다**. 총판 정산 입금 실적으로 확인되기 전에는 계산의 입력으로 쓰지 않는다.
- **CPC·CPL·CPI 손익분기점은 계산하지 않는다**(정산액·환수·지원액·전환율이 모두 미확정).
- 광고비 한도는 수익성 계산과 별개로 **일 10,000원 · 누적 30,000원(계정 전체 합산)** 그대로다. 이 문서의 어떤 수치도 한도 변경 근거가 아니다.
- 정산 입금까지 약 1개월(대표 진술). 정산 입금 확인 전 광고비 증액 금지.

### 7.2 정책 자료 재조회 결과 (11/22)
- 대표가 받은 **2026-11-06 기준 KT·LG·SK 유선 가정용 정책표(이미지)와 개인단가.ods**는 이 저장소·개발 환경에 없다(업로드·커밋 이력 없음). 그래서 **통신사별 수수료·설치비·상품권 가이드·추가 지원액 금액은 이번에 확인하지 못했다.**
- 저장소 안의 정책 값은 모두 시험용 가상값(예: 11,111원·2,222원·3,333원)이며 실제 정책이 아니다.
- 대표 진술로 확인된 조건(금액 아님): 가입 후 **1년 이내 해지 시 수수료 환수**, **약정 3년 설치비 안내**와 **기존 회선 12개월 유지 안내** 필수, 사업자 없이 **3.3% 원천징수** 딜러로 진행, 정산 입금 약 1개월.

### 7.5 판정 규칙(운영)

- 화면은 입력값마다 '확인/미확정' 표시를 붙이고, 미확정이 있으면 예산 승인 버튼을 비활성(설계).
구현: 순수 함수 + 관리자 화면, 외부 호출 없음. PM 승인 전 구현하지 않는다.
