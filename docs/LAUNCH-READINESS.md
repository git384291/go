## 2. 검색 노출 — 공개 전 해제 변경안 (적용하지 않음, PM 검수용)

이미 들어간 것(닫힌 기본값): 페이지별 고유 제목·설명, `robots.ts`·`sitemap.ts`, 공식 주소 검증, `/admin`·`/api` 상시 차단, 키보드 초점 표시. 320·360·390px에서 가로 넘침이 없음을 확인했다.

공개 시 필요한 변경(모두 승인 필요):
1. 공식 도메인 확정 → 운영 환경변수 `PUBLIC_SITE_ORIGIN=https://<확정 도메인>` 설정
2. 운영 환경변수 `SEARCH_INDEXING=allow` 설정 → robots 허용(관리자·API 제외), sitemap 3개 경로(`/`, `/products/internet-tv`, `/privacy`)
3. 루트 layout의 noindex 해제 변경안:
   ```diff
   -  robots: { index: false, follow: false }, // 1단계 공개 승인 전까지 검색 노출 차단
   +  robots: searchIndexingAllowed() ? { index: true, follow: true } : { index: false, follow: false },
   ```
   - layout이 요청 시점에 환경을 읽도록 `generateMetadata`로 바꿔야 한다.
   - 시험 S5는 "운영 + allow + 공식 주소일 때만 index"로 바꾼다.
4. `/consult`는 접수 개방 승인 전까지 sitemap에서 뺀다.
5. 구조화 데이터는 화면에 실제로 표시되고 검증된 정보만 쓴다. 지금은 넣지 않는다. 사업자 정보·주소·평점·후기·가격이 확정되지 않았다.
6. 공개 후 Search Console 소유 확인은 도메인 소유자가 직접 한다. 순위·유입은 보장하지 않는다.

참고: [Google 검색엔진 최적화(SEO) 기본 가이드](https://developers.google.com/search/docs/fundamentals/seo-starter-guide?hl=ko)

## 4. 광고 지표 정의 (`src/content/adMetrics.ts`)
| 지표 | 식 | 분모 0·미수집 |
|---|---|---|
| CPM | 비용 ÷ 노출 × 1000 | null |
| CPC | 비용 ÷ 클릭 | null |
| CTR | 클릭 ÷ 노출 × 100% | null |
| CPA | 비용 ÷ 해당 단계 전환 수 | null |
| CVR | 해당 단계 전환 수 ÷ (명시한 분모: 클릭 또는 방문) × 100% | null |
| ROAS | 확인된 귀속 매출 ÷ 비용 × 100% | 매출 미확인이면 null |
| CPI | 해당 없음(앱 설치 캠페인 없음) | — |

- **집계 모델(입력에 명시):**
  - `cohort`(동일 유입 코호트): 기간 안 유입자 기준으로 귀속 창 `windowDays`(1~365일, 0일 없음) 안의 전환·매출만 센다. 단계 수는 단조 감소여야 하고, ROAS는 이 모델에서만 계산한다.
  - `occurrence`(기간 발생 집계): 기간 안에 일어난 전환 수다. 지난달 접수가 이번달 개통될 수 있어 단계 간 비교를 하지 않는다. 매출을 넣으면 거부하고 ROAS는 null이다.
- **실행 시점 검증:** 달력상 유효한 날짜(윤년 포함), 모델·유입·광고 유형·전환 단계 키 enum, 횟수는 안전한 정수 0 이상, 금액은 원 단위 정수에 상한 1조 원. 잘못된 값은 계산하지 않고 거부한다.
- **입력 필수 맥락:** 기간(Asia/Seoul), 출처, 유료/자연/직접/추천 구분, 광고 유형(검색 SA / 디스플레이 DA / 소셜), 비용의 VAT 포함 여부
- **전환 단계:** 상담 접수 → 가입 → 개통 → 정산. 단계마다 따로 세며, 뒤 단계가 앞 단계보다 크면 입력을 거부한다.
- **매출:** 실제 인정된 판매 수수료에서 환수·취소를 뺀 값이다(음수 가능). 귀속 기간 없이는 계산하지 않는다. 통신사 월요금, 고객 계약액, 개당 예상 마진은 매출이 아니다.
- **자연 검색:** 비용이 있으면 입력을 거부한다. 비용 지표와 ROAS는 null이다.
- **SA/DA와 CTA:** SA/DA는 광고 유형이고 CTA는 버튼 문안이다. 같은 비용 지표로 비교하지 않는다. 유형별로 비교하고, 클릭 → 접수 전환으로 평가한다.
- **UTM:** 운영자가 미리 등록한 비식별 캠페인 코드 조합(`src/content/utm.ts`의 `UTM_REGISTRY`, 최대 50개)과 **정확히 일치**할 때만 남기고, 미등록 값은 전부 버린다(`matchUtm`).
  - 정규식으로는 영문 이름·개인 식별 코드·주소를 판별할 수 없다(예: `john.smith`). 그래서 형식 검사로 개인정보 제거를 **보장하지 않는다.**
  - 등록부는 캠페인 단위로만 쓰고 고객·개인별 코드를 등록하지 않는다. 현재 등록부는 비어 있다(광고 미집행). URL 원문을 로그에 남기지 않는다.
- **중복 집계 금지:** 광고 클릭과 접수 전환을 같은 이벤트로 두 번 세지 않는다.
- **이번 묶음에서 켜지 않은 것:** 운영 트래커, 픽셀, 쿠키, 실제 이벤트 수집, 외부 전송, 새 DB 테이블. 관리자 지표 화면은 기존 인증 + owner 범위로만 설계한다. 공개 화면에는 매출·내부 수치를 노출하지 않는다.
- **실측 전 금지:** 목표 수치 조작, 자동 입찰 최적화, 예산 증액

## 5. 총판 확인 요청 템플릿 (작성만, 발송하지 않음)

> 사용자 지시 없이 공급처에 보내지 않는다. 비밀번호·로그인 정보·고객 정보·주민번호·신분증·계좌는 이 메시지에 넣지 않고, 회신으로도 받지 않는다.

```
[딜러 ○○○] 인터넷·TV 영업 관련 확인 요청드립니다.

1. 공식 접수 경로

     딜러별로 구분되는 접수 주소나 코드가 있는지 알려 주세요.
2. 딜러 유입 식별
   - 그 경로로 들어온 신청이 제 실적으로 잡히는 방식(딜러 코드, 전용 링크 등)을 알려 주세요.

   - 개인(사업자등록 없음) 딜러로 온라인 광고가 가능한 매체·표현 범위와 금지 사항(통신사 명칭·로고 사용,
     "공식" 표현, 가격·사은품 표기 등)을 서면으로 알려 주세요.
   - 광고 문안 사전 검수가 필요한지도 알려 주세요.

   - 정책표가 바뀔 때 최신본과 적용 시작일을 받는 방법을 알려 주세요(가정용·SOHO 구분).
5. 민감 자료 전달 경로

감사합니다.
```
