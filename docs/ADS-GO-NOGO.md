# Google Ads 자동 광고 — 운영 전 점검표·롤백·GO/NO-GO (PM 11/25)

현재 판정: **NO-GO** (실계정 검증 미완료). 이 문서는 집행을 요청·승인하지 않는다. 실제 집행은 사용자 + PM의 명시적 GO 뒤에만.

## 2. 내부 한도와 Google 실제 집행의 차이 (코드 검수 결과)

- 내부 한도(DB 0020·0021, 계정 전체 잠금으로 동시 집행 직렬화): 날짜별 최대 10,000원, 누적 30,000원, 집행 최대 3개 날짜.
- Google은 하루 예산의 최대 2배까지 쓸 수 있음 → 매체 하루예산 = 승인액 ÷ 2로 만들어 날짜별 최대 청구액이 승인액을 넘지 않게 설계. 종료일은 DB가 정하고 Google `end_date_time`에도 넣음.
- 보고 지연: 비용 보고가 비면(null) 감시가 UNKNOWN으로 기록 → 새 집행 차단. 이미 켜진 캠페인의 지출은 위 2배 구조로 상한.
- 실제(Google Ads) 어댑터에는 캠페인을 ENABLED로 켜는 코드 경로가 없음(항상 PAUSED 생성, ENABLED 생성 설정도 11/26 제거, 일시정지만 가능). 0035 예약 스케줄러의 켜기는 모의 어댑터 전용이며 실제 어댑터면 `LIVE_ENABLE_FORBIDDEN`으로 거부. **켜는 일은 사람이 Google Ads 화면에서** → 그 순간이 승인 게이트. 화면에서 직접 켠 캠페인(launch 기록 없음)은 정기 감시의 중지 대상이 아님(새 집행만 막음) — 9번 항목으로 관리.

## 3. 롤백(문제 발생 시, 순서대로)

1. Google Ads 화면에서 해당 캠페인 **일시정지**(가장 빠름). 또는 관리자 화면·감시의 pause.
2. 관리자 화면에서 광고 예산 승인 **철회**(새 집행 차단).
3. 운영 환경변수 `AD_PLATFORM`을 비우거나 `mock`으로 → 앱이 Google로 더 보내지 않음.
4. 결제 수단·청구 확인(Google Ads 결제 화면). 초과 청구가 있으면 Google 지원에 문의.
5. 원인·시각·금액을 PM에게 보고. DB 원장·감사 기록은 지우지 않는다.

## 4. GO 요청 조건

1~9가 모두 ✅ → PM 검토 → 사용자 명시적 승인(예산·기간·CPC·키워드) → 그때 사람이 Google Ads 화면에서 켠다. 그 전에는 활성화·입찰·예산 변경·자동 게시 금지.
