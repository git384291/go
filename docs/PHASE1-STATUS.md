## 현재 코드의 제한

- 인터넷+TV만 활성 상품이다. 다른 상품은 예약 상태로 유지한다.
- 실제 고객정보 수집과 외부 상담 채널은 비활성이다.
- 관리자 로그인 폼은 미리보기이며 입력이 비활성이다.
- `src/server/auth/requireStaff.ts`에 `openStaffSession`은 있지만 로그인 완료 경로에서 호출되지 않는다.
- 관리자 화면은 가상 데이터이며 운영 환경에서는 잠긴다.
- 로컬 DB 테스트 성공은 Supabase Auth·연결 풀러·실제 배포 환경 검증을 대신하지 않는다.

## 다음 개발 순서

1. 가상 데이터 전용 Supabase 개발 프로젝트의 연결 환경을 준비한다. 새 계정·유료 프로젝트 생성은 이 기록으로 승인하지 않는다.
2. 관리자 이메일·비밀번호 로그인 → TOTP 확인 → 검증된 `aal2` 클레임 → `openStaffSession` 연결을 구현한다.
3. 로그아웃 시 DB 세션 폐기와 Auth 로그아웃을 연결한다. 비활성 직원·미등록 직원·만료/폐기 세션·다른 사용자의 세션은 거부되는지 검증한다.
4. 개발 DB에서 역할 로그인·RLS·서명 검증·풀러 호환을 확인한다. 실제 고객정보는 사용하지 않는다.
5. SEC-01~03 재검수 근거를 정리한다. Vercel 검수 배포가 준비되면 별도로 IP 위조 방어를 확인한다.

## 자동 작업 범위와 연결 상태

- 사용자는 GitHub·터미널을 통한 기존 개발·수정·검증 진행을 요청했다.
- 현재 작업 환경에서 저장소 clone 및 GitHub 조회가 가능하다. 변경은 위 기능 브랜치에 한정한다.
- Claude 도구/CLI와 사용자 Mac mini의 원격 터미널 연결은 확인되지 않았다. 이 환경의 터미널 실행을 Mac 실행으로 보고하지 않는다.
- Supabase 개발 프로젝트 연결은 현재 작업에 제공되지 않았다. 실제 인증 연동 검증은 미완료로 기록한다.
- 비밀번호·토큰·DB 접속 정보는 채팅이나 저장소에 기록하지 않고, 연결된 실행 환경의 비밀값 설정을 사용한다.
- `main` 병합, 운영 배포, PHASE 2 활성화, 실제 고객정보 수집은 별도 명시 승인 전까지 보류한다.
